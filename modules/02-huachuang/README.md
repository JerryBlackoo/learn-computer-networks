# 模块 02：成帧与不可靠链路上的交付

## 学习目标

- 在内存信道 `KexinLianlu` 上实现**成帧**：序号、FIN 标志、简单校验和。
- 理解**固定接收窗口**内对乱序分片的缓存与按序交付（非完整 TCP，无双向 ACK 信道）。
- 将「坏帧丢弃」与「乱序等待」区分开，为模块 11 故障注入实验打基础。

## 核心概念

- **分片**：长应用报文切成 `duan_max` 大小的块，每块独立成帧。
- **序号空间**：单字节序号（教学简化）；接收方维护 `next` 期望序号。
- **窗口**：仅缓存 `seq ∈ [next, next + chuangkou)` 的乱序帧，窗外丢弃以防内存膨胀。

## 不变量

- 校验和错误的帧必须丢弃，不得推进 `next`。
- 仅在收到连续序号且 FIN 到达时返回完整 `bytes`；否则返回 `None`（可多次调用 `jieshou`）。

## 常见失败模式

| 现象 | 可能原因 |
|------|----------|
| 永远收不齐 | 丢包且无重传（本模块不实现 ACK 重传，见模块 05 直觉） |
| 乱序卡死 | 未实现窗口内缓存 |
| 静默损坏 | 未校验 checksum |

## 作业 API

- `HuachuangTongdao.chuanshu(shuju)`：发送端驱动，向链路注入帧。
- `HuachuangTongdao.jieshou_wanzheng()`：接收端取完整报文（可多次 drain 链路）。
