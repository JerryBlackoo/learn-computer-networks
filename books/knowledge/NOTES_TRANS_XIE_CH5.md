# 谢希仁第 5 章运输层 · 精读笔记

## 本章必须搞清的概念（教材）

1. 运输层为应用进程提供**逻辑通信**  
2. 端口与套接字  
3. UDP / TCP 特点  
4. 不可靠网络上的可靠传输（停等、ARQ）  
5. 滑动窗口、流量控制、拥塞控制、连接管理  

## 为何需要运输层？

IP 只交付到主机；一台主机有许多进程。运输层用**端口**复用/分用，实现进程到进程。路由器转发只用下三层。

## TCP vs IP / UDP（答案）

| | TCP | IP | UDP |
|--|-----|----|-----|
| 连接 | 面向连接 | 无连接 | 无连接 |
| 范围 | 端到端 | 主机到主机（逐跳） | 端到端 |
| 可靠 | 是 | 否 | 否（可选校验和） |

- **5-6**：链路层滑动窗口管相邻节点；TCP 管端到端字节流。  
- **5-7**：有了 TCP，链路/网络层不必再做端到端可靠（局域网常只做 CRC）。  
- **5-15**：初始序号不能固定，避免旧连接报文与新连接混淆。  
- **5-19**：即使链路全可靠，端系统仍可能出错 → TCP 仍必要（E2E）。

## 拥塞控制四机制

慢开始、拥塞避免、快重传、快恢复 → `CongestionControl`。

## 连接管理（OCR ≈p260 连接释放）

- 三次握手建立；四次挥手释放。  
- FIN 即使无数据也消耗一个序号。  
- **半关闭**：一方 FIN+ACK 后另一方向仍可传数据（CLOSE-WAIT / FIN-WAIT-2）。  
- TIME-WAIT 等待 2MSL。期末考 Seq/Ack、MSS、吞吐量。

## 传输效率与病态（OCR ≈p248）

- **持续计时器**：收到零窗口后探测，打破死锁。  
- **Nagle 算法**：小字节先发一个，其后缓存，收确认后再成段发送；达半窗口或 MSS 可立即发。  
- **糊涂窗口综合征**：接收方每次只腾出 1 字节并通告窗口 1 → 效率极低；接收方应等够一个 MSS 或一半缓存再通告。
