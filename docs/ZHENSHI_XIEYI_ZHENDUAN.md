# 真实协议诊断路线（知识覆盖计划第 11 节）

本文件是 **Computer-Networks-Learning-Path** 对「网络协议与真实网络诊断」的升级说明，与仓库内模块 01–12 的**教学仿真**并列，不替代 `docs/TEACHING_GAPS.md` 中的诚实边界。

## 目标与预算

- **目标**：能对自己控制的两端服务，完成一次可复现的请求链观察，并在「上传变慢 / 流式卡顿 / 连接重置」三类场景中，建立 **报文 → 套接字 → 进程 → 应用请求** 的证据链，指出瓶颈更可能在哪一层，并列出仍无法判断的内容。
- **预算**：约 60–100 小时（6–10 周，按每周约 10 小时有效学习估算）。
- **毕业交付**：结构化网络诊断报告（模板见模块 13 `moban_biyelun()`），附固定环境与版本说明。

## 六段学习顺序（与计划对齐）

### D01 实际请求链

新增可运行单元：`projects/wire_probe`，通过真实 socket 测量 HTTP/TLS 请求；`make verify` 自动启动服务并验证响应与证书。原始报文、重传和拥塞仍需抓包，不能从 recv 次数推断。

在自有两个服务之间观察 DNS、TCP、TLS、HTTP。记录各阶段时间与报文身份（五元组、TLS 会话、HTTP 流 ID 若适用）。讲义不写外链；规范入口见 `sources/catalog.toml` 中 `rfc.dns`、`rfc.tcp`、`rfc.tls13`、`rfc.http_semantics`。

### D02 TCP 深化

对照：状态与序号/ACK、窗口、重传、RTT/RTO、拥塞反应。用模块 05 与 10 的教学 API 先推演，再用本机 trace 标出差异点（例如 Karn/Jacobson、SACK 未在课内实现）。

### D03 网络故障（隔离环境）

在本地命名空间或容器网络中注入 loss、delay、reorder、带宽上限。区分：连接建立失败、传输层重传风暴、应用层读/写超时。可与模块 11 的 `diubao/chongpai` 分类对照，但须说明内存信道与真实链路的映射假设。

### D04 应用协议（窄实验）

连接复用、HTTP/2 多路复用、QUIC 与 HTTP/3 的分层差异：以阅读 RFC 与小型客户端实验为主，不要求实现完整协议栈。

### D05 路由分支（选修）

小型 namespace / 虚拟路由：转发表、默认路由、OSPF/BGP **概念**入门。模块 04 的小图 DV/LS 为算法直觉，不等同于生产 FRR。

### D06 诊断项目

三个必修案例（合成 fixture 在模块 13，真实复现为 not-run）：

1. 上传变慢  
2. 流式卡顿  
3. 连接重置  

每个案例必须填满四层证据，并给出 `yixuan_pingju_ceng` 与 `weizhi_neirong`。

## 验收标准（诊断专用）

- 环境、工具版本、两端服务版本可复现；抓包仅针对**自己的实验流量**。
- 每个案例有完整证据链；缺任意一层则视为未完成。
- 明确区分：**机制课内已验证**、**本机 not-run 已观察**、**仍未知**。
- 不得用「已加 TLS」替代应用层超时、背压或代理缓冲分析。
- 另一位操作者可按你的说明启动双服务并复现至少一个案例的时间线。
